# Проверка перед публикацией (в том числе из Fork)

Gitleaks проверяет публикуемые файлы и всю доступную локальную Git-историю.
Используются стандартные правила и дополнительные проверки API-учётных данных
и буквальных IPv4-адресов. Приватные ключи, keystore, .env, локальные SDK-настройки
и сгенерированные build-файлы не допускаются к публикации.

Сканер не гарантирует обнаружение любого возможного секрета. API как код,
интерфейс или публичный URL не является секретом сам по себе; запрещены
ключи доступа, токены и приватные реквизиты. Найденные значения редактируются
в выводе. Отчёты сохраняются только локально в игнорируемой `.security-reports/`.
Не добавляйте их в Git.

## Подключение

Установить Gitleaks из официального релиза (на этом Mac проверена версия 8.30.1).
Скачать под свою платформу и проверить SHA-256 по официальным checksums.
Бинарный файл должен быть в PATH, `~/.local/bin/gitleaks` или GITLEAKS_BIN.

```sh
git config --local core.hooksPath .githooks
chmod +x .githooks/pre-commit .githooks/pre-push gradlew
python3 scripts/security.py
python3 -m unittest discover -s scripts/tests -v
```

Hook pre-commit блокирует секреты; pre-push дополнительно запускает:

1. Проверку чистого рабочего дерева и соответствия отправляемой ветки HEAD.
2. Gitleaks для файлов и истории (без проекта `.gitleaksignore` и обхода через allow-комментарии).
3. Тесты самой защиты: пропуск чистого файла, блокировку синтетического токена,
   IP-адреса, PEM-заголовка, отсутствующего сканера, грязного дерева и ошибки команды.
4. Сборку и unit-тесты Android с фактическим повторным выполнением задач.
5. Измерение и проверку 100% покрытия GameViewModel в Unscramble.
6. Инструментальные сценарии на подключённом эмуляторе; для ActivityLifecycle —
   реальный adb-сценарий запуска, Home, возврата и поворота.

Любая ошибка прерывает push. Нужны Android SDK, совместимый JDK и запущенный
эмулятор. Проекты проверяются последовательно, так как сценарии поворачивают
одно устройство. Подключённые Git hooks работают и при нажатии Push в Fork.
После клонирования каждый разработчик должен подключить hooks указанной командой:
Git намеренно не включает локальные hooks автоматически.

Не используйте `--no-verify` или `core.hooksPath=/dev/null`. Отправляется только
проверенная текущая ветка, не произвольные локальные refs. Наличие SSH-ключа
разрешает Git push в существующий репозиторий, но не создание нового репозитория
через GitHub API: для этого нужна авторизованная сессия GitHub/Fork.
